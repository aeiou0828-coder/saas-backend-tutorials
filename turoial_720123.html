商城 · 操作与运营教程

玩家用积分、活跃度、幸运值、余额兑换各类商品，把积累的资产变现成多样奖励。

目录一、功能概述二、新增商品三、商品类型四、兑换价格五、公共配置六、商品管理七、兑换审核与记录八、实物订单九、客户端展示十、运营建议十一、常见问题

一、功能概述

是什么 商城让玩家用积分、活跃度、幸运值、余额兑换各类商品；商品在后台上架管理，兑换可配是否审核，实物商品走实物订单发货。
解决什么 把玩家在各模块积累的积分、活跃度、幸运值变现成可兑换的奖励出口，既消耗资产又拉动活跃。
兑换类型 玩家用什么换：消耗 积分 / 活跃度 / 幸运值 / 余额（一个商品可设多种，玩家用任意一种即可兑）。
商品状态 出售中、待上架、已售罄、已删除、全部商品。
兑换状态 待审核、已兑换、被拒绝；是否审核由商品的【是否需要后台审核】决定。

二、新增商品

在商品列表右上点【新增商品】打开弹窗，如下图。
序号 字段 说明
1 品牌 / 币种 商品适用的品牌与币种；多品牌站点配置共用，勾选哪些品牌就对哪些开启。
2 排序权重 数字越大客户端越靠前展示。
3 商品类型 五选一，决定兑换后给玩家什么（见第三节）。
4 商品规则限制 按所选商品类型展开对应配置（见第三节）。
5 商品名称 支持多语言。
6 展示分类 只有 1 个分类时客户端不展示分类页签，≥2 个才按页签展示。
7 兑换价格 可统一价或按 VIP 等级分档（见第四节）。
8 商品缩略图 全部通用或按语言分别上传；尺寸 220×220，可上传多张、展示只选 1 张。
9 库存数量 无限量或固定（固定可设 1-12 位整数）；库存为 0 时兑换按钮置灰、状态转已售罄。
10 初始兑换次数 纯营造热度的客户端展示值，不减库存、无逻辑计算；客户端展示兑换数 = 初始兑换次数 + 实际兑换数。
11 每日兑换次数上限 一个玩家一天该商品最多兑换次数，超过置灰。
12 上下架方式 / 时间 自动（按上下架时间自动执行）或手动（自行操作、忽略时间，手动优先级更高）；选自动时设上架与下架时间，只能选当天及以后、精确到时分。
13 商品标签 热门 / 推荐 / 新，客户端角标展示；当前单选、不可新增。
14 是否需要后台审核 不需要=兑换后直接到账；需要=兑换后进待审核，人工通过才到账。
15 是否需要简介 无简介则玩家点商品直接兑换；图文介绍则点商品先弹详情。

三、商品类型

商品类型决定兑换后给玩家什么，共五种。

商品类型 规则配置
折扣券 选择已配置的折扣券。
砍一刀抽奖次数 选择活动 + 设免费抽奖次数；发放的是新砍一刀的次数。
盲盒抽奖次数 选盲盒类型（小 / 大 / 超级）+ 免费抽奖次数 + 有效天数。
实物 兑换后产生实物订单，后台跟进发货（见第八节）。
自定义 名称 + 图片，可用于虚拟服务（如某地一日游等），内容可自由定义；兑换成功即扣消耗、状态为已兑换，无需后续履约，对玩家就是一条兑换成功记录。

四、兑换价格

兑换价格支持按 VIP 等级设置：

关闭 全等级统一价，所有 VIP 用同一兑换价。
开启 按 VIP 等级（可多选）分别设消耗积分、消耗活跃度、消耗幸运值、消耗金额，可配多档；至少设一种类型价格，若同时设多种，则玩家用任意一种方式都可兑换。

五、公共配置

公共配置是商城统一规则，在商品列表右上点【公共配置】打开。
可兑换层级 / VIP 限定哪些会员层级、VIP 等级可参与兑换。
可兑换终端 限定可兑换的客户端终端。
更多兑换限制 短信、邮箱、生日、银行卡、虚拟货币、三方钱包、收款方式、真实姓名、生物识别、KYC、首充等门槛；同类型活动只能申领 1 次、充值后且未投注才能领、仅注册设备号领取、同 IP / 同姓名次数等；玩家不满足时兑换会弹提示。
是否展示库存 / 兑换次数 控制客户端是否展示商品库存、兑换次数。
商品标签 维护热门 / 新 / 推荐标签。
商品分类 维护客户端展示分类，支持多语言、可新增删除；未新增分类则不展示分类、为系统默认。
规则说明 自定义或系统自带。

六、商品管理

商品列表按状态分页签，可按时间、品牌、币种、商品类型、兑换类型、展示分类等筛选。客户端只展示出售中的商品。

行操作 修改、详情（可看最近 30 次操作历史）、下架、删除。
批量操作 批量下架、批量设置分类、批量设置标签、批量删除；排序支持拖动、置顶、批量权重值排序（权重越大越靠前）。
上下架流转 自动且未到上架时间为待上架、到点转出售中；后台手动上下架后该商品转为手动方式、不再走计划任务（手动优先级更高）。
已售罄 库存为 0 即已售罄，可重新上架；创建时库存填 0 直接置已售罄。
商城开关 商城总开关，关闭后客户端不展示商城。

七、兑换审核与记录

7.1 兑换用户

参与过商品兑换的玩家都进该列表，一个玩家一条，展示剩余积分、活跃度、幸运值，以及已兑换、待审核、被拒绝数量和最后兑换时间。

7.2 兑换记录与审核

兑换记录按状态分待审核、已兑换、被拒绝、全部兑换记录，记录玩家、商品、兑换类型、兑换价格、登录 IP / 设备 / 指纹、兑换时间等。
是否需审核 由商品的【是否需要后台审核】决定：不需要则兑换后直接到账；需要则进待审核，人工通过后才到账。
通过 / 拒绝 待审核记录可通过或拒绝，弹窗会显示选中玩家数据供二次确认，可填前台 / 后台备注；支持批量通过、批量拒绝。
审核失败返还 审核未通过需返还玩家兑换消耗的积分、活跃度、幸运值、余额；余额返还记账变（兑换成功扣余额、失败返余额）。

八、实物订单

实物商品兑换后产生实物订单，需后台跟进发货。

订单内容 玩家、商品、兑换时间、收货姓名、收货地址、邮编、联系电话、订单状态、快递单号、快递公司、发货时间、前后台备注。
订单状态 待发货 → 已发货 → 已签收；玩家可签收或后台强制签收，异常可强制取消。
收货信息 收货地址与联系电话加密存储，按前 2 位 + 4 个星号 + 后 2 位展示；有默认地址则兑换后自动带入，可改。
发货处理 后台核对收货信息后填快递单号、快递公司发货；查看完整收货地址、电话需输入安全码。

九、客户端展示

商城入口 商城入口可配在多处：首页（中部导航、侧边栏、底部菜单、页脚）、营销广告位、我的页面（顶部、列表）。
玩家使用 玩家进入商城浏览并兑换商品；积分、活跃度、幸运值不足时，可去对应模块赚取后再来兑换。

十、运营建议

场景 建议 提示
养成逛商城 折扣券、抽奖次数设低消耗，让玩家用积分、活跃度轻松兑到，培养逛商城习惯。 低门槛走量，先把玩家引进来。
拉高吸引力 用实物或高价值商品做橱窗，提升商城整体诱惑力。 实物要算清发货成本，库存别铺太大。
控制兑出成本 用兑换价格按 VIP 分档、配多种消耗资产，把高价值商品价格抬到合理水位。 至少设一种价格，设多种则任意一种可兑。
制造稀缺 热门商品设固定库存 + 每日兑换上限，配合初始兑换次数营造热销感。 初始兑换次数只影响展示、不减真实库存。
配合活动节奏 限时商品用自动上下架按计划上线下线；临时调整用手动及时上下架。 手动优先级高于计划任务。
风控 高价值商品开后台审核，叠加多重兑换限制（KYC、绑卡、同设备同 IP 等）防多号薅。 审核失败会自动返还玩家消耗。
效果监控 关注兑换量、各资产消耗、库存周转、审核拒绝率，按数据调商品与价格。 某商品兑换异常高，回查价格是否偏低或被薅。

十一、常见问题

Q：兑换后多久到账？

A：取决于商品的【是否需要后台审核】：不需要则兑换后直接到账；需要则进待审核，后台通过后才到账。

Q：同一商品能对不同 VIP 等级设不同价格吗？

A：可以。把兑换价格的【按 VIP 等级设置价格】开启，即可按等级分档设消耗积分、活跃度、幸运值、金额。

Q：初始兑换次数会占用真实库存吗？

A：不会。初始兑换次数只用于客户端展示、营造热销感，不减库存、不参与任何计算。

Q：审核没通过，玩家扣的积分/余额会退吗？

A：会。审核未通过自动返还玩家兑换消耗的积分、活跃度、幸运值、余额。

Q：自定义商品兑换后怎么处理？

A：自定义商品兑换成功即扣消耗、记为已兑换，对玩家就是一条兑换成功记录，具体使用线下处理。
